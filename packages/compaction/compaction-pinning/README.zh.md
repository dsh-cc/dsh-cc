# @dsh-cc/compaction-pinning

[English](README.md) | 中文

压缩过程中的治理消息钉扎。行为治理类消息——回合规则提醒、编辑后验证的恢复提示——以普通 `user/message` 事件的形式传输，因此摘要压缩可以把包含它们的整个区间替换成一条检查点消息，让这些指令只剩下摘要恰好保留的部分。本插件把这些消息逐字捕获进一个有界的按会话环形缓冲，并在检查点提交后逐字恢复它们，使一条治理指令的约束力贯穿整个会话，而不是只维持到下一次压缩。

## 工作方式

- **捕获：** 一个纯观察的 `session/event` 监听器。对每条 `source.kind` 属于已配置种类的 `user/message`，把**整个**消息对象（内容块加 source 元数据，按引用保留，绝不克隆或解构）连同其 seq 与时间戳存入该会话的环形缓冲。缓冲按条目数和估算字节数做 FIFO 上限；最旧的条目先被淘汰。
- **恢复：** 压缩的摘要会列出被遮蔽的 seq；其中的钉扎消息在检查点提交后按原 seq 升序逐字重新追加，每条各自追加一次，以便来源边界保留。恢复后的消息以新的 seq 自然重新进入环形缓冲，因此再次被遮蔽会自愈而不是死循环。
- **有界：** 两个上限（条目数与字节数）加一份固定种类表，让捕获开销低、恢复批次小。事件观察回调内绝不追加消息——恢复从代理的 pre-step 接缝排空。
- **默认：** 开启，种类为两种持久的行为约束来源。关闭该功能会停止捕获与恢复；环形缓冲从不被回溯重建。

## 配置（命名空间 `cc-compaction-pinning`）

热读取：每条消息都会重新读取配置值，因此修改设置立即生效。

| 键 | 类型 | 默认 | 范围 / 含义 |
|---|---|---|---|
| `enabled` | bool | `true` | — 关闭后停止捕获与恢复。 |
| `pinned-source-kinds` | string[] | `['turn-rules','edit-recovery-hint']` | 每项 ≤ 64 字符；空列表或全部非法时回退到默认两项。 |
| `max-pinned` | int | `16` | `1..64` — 环形缓冲条目上限。 |
| `max-pinned-bytes` | int | `16384` | `1024..262144` — 环形缓冲字节上限。 |

```json
{
  "cc-compaction-pinning": {
    "max-pinned": 24,
    "pinned-source-kinds": ["turn-rules", "edit-recovery-hint"]
  }
}
```

## 已知缺口

- **恢复代际缺口（resume-generation gap）。** 环形缓冲是进程内存。本进程恢复的会话里发生的压缩，可能遮蔽本进程从未捕获的钉扎消息；生产者会随时间重新触发（尤其回合规则提醒），但中间这段没有保护。挂载时从会话自身的投影重建当下已存在的钉扎消息，是后续版本的可行方向，此处刻意不做。
- **请求内一步缺失（in-request one-request gap）。** 在请求重试内部触发的压缩（上下文溢出、模型切换）发生在其重试请求的消息已派生之后，而会话事件观察者无法追加消息（重新进入发布流程会抛错）。钉扎消息在下一步恢复，因此恰好有一个请求可能缺少它们。要彻底闭合，需要引擎侧接缝，把钉扎消息从区间选择中豁免。
- **摘要无输入联动。** 摘要器看不到恢复的内容；恢复对应的是提交后的补救措施，而不是修复摘要本身。

## 用法

```ts
import type { Context } from '@deepseek-ai/cordis'
import * as CompactionPinning from '@dsh-cc/compaction-pinning'

export function apply(ctx: Context): void {
  ctx.plugin(CompactionPinning)
}
```

普通插件，非 isolate。配置位于 `<dshHome>/settings.json`；本包注册自己的命名空间用于 `/config` UX 与校验，并在每条消息上重新读取它，同时导出原始的用户层读取器，供需要完全排除项目作用域的调用方使用。
