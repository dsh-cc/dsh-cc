# Writing with source evidence

## Claims and reasoning

Keep facts separate from a source's account of those facts.
Keep an interpretation separate from a documented event.
Do not turn a correlation into a cause without an explicit argument.
Do not infer an author's intention from an effect alone.
For an evaluation, state the criteria.
For each argument, state its premises, warrant, assumptions, and limits.
For each main conclusion, give an explanation or state that it is a direct fact.
An honest undetermined answer can be the correct result.

## Sources and quotes

Use the source edition and context that the project actually contains.
Preserve the exact source wording for a quotation.
Identify translations, paraphrases, omissions, and other transformations.
A matching quote does not by itself support every interpretation of that quote.
Different copies of one source are not independent evidence.
Keep source doubts and conflicting evidence visible.

## Body and report

Answer the required questions in the body.
Put necessary conditions and uncertainty next to the affected statement.
Discuss material objections in the body, not only in the final report.
Use `〔src:ws:<path>#La-Lb〕` source markers where applicable.
An optional `〔claim:<id>〕` marker is an author aid, not a source citation.
If you remove a claim marker, bind and review the changed body again.

A high grade applies only to the checked claim, scope, evidence, and argument.
Do not present a model grade as an objective truth certificate.
The runtime report records current assessments, reasoning, disputes, and evidence gaps.
Use its status; do not invent a stronger one.

## Language and task scope

Use the user's requested language and document type.
Keep the vocabulary and structure suitable for the reader.
For a review-only task, preserve the body until the user authorizes edits.
Do not require ASD-STE100 for a literary article unless the user requests that style.
Document language rules do not change the evidence requirements.
