# dsh-cc-bundle-shell

English | [中文](README.zh.md)

The CC shell **host-plane infra** bundle. This package carries the pieces that are genuinely host-level — the tools-registry swap with deferred-name support — plus the `cc-shell-glue` plugin *code* (the glue code still lives here, but its mount action is performed by the CC preset, not this bundle's patch). All agent-facing composition — tool-search, skill loader, memory, coordinator, worktree/sleep/notebook/structured-output tools, the 25 slash commands, the hook bridge, output-style rendering — moved to the [`@dsh-cc/preset-cc`](../../preset/cc/README.md) composition package, so it can be isolated per preset instead of leaking into every mode 〔src:ws:packages/preset/cc/README.md#L10-L10〕.

## What it does

- **Tools registry swap.** Disables the in-box `tools` row and remounts `@dsh-cc/tools` 〔src:ws:docs/plans/2026-11-07-harness-0.2.2-rc.1-migration.md#L125-L129〕. `reserve()`/`isAdmitted()` join the restrictable-name universe, so permission gates can name deferred tools before they load; the shipped behavior otherwise matches upstream 〔src:ws:packages/core/tools/README.md#L50-L50〕. The base row's `DSH_TOOLS_MODE` toggle is carried forward (`$DSH_HOME` / `process.cwd()` semantics unchanged) 〔src:ws:docs/plans/2026-11-07-harness-0.2.2-rc.1-migration.md#L127-L127〕.
- **Host agent-plane vacating.** The 22 rows `dsh-base` declares for the agent plane (tool-bash, tool-fs, tool-web, subagent tools, workflow/ralph, plan mode, compaction, instructions, todo, …) are disabled here by ID, so the CC preset owns that plane 〔src:ws:packages/bundle/cc-acp/README.md#L5-L5〕. They live in this bundle rather than in the surface bundles because the vacating is a property of the shell layer: both the TUI and ACP lanes mount this bundle, and a second surface must not be able to re-add the host plane. Disabling rather than deleting keeps the shared base usable by non-CC profiles.
- **Glue plugin code (mounted by the CC preset).** `cc-shell-glue` mounts what a cordis patch row cannot express statically: on-disk Claude Code plugins, `.mcp.json` server wiring, and a built-in plugin `mcp` seam (`cc-mcp-seam`, so plugin `mcpServers` mount via mcp-client). Default plugin discovery is the dual-home merged view: `enabledPlugins` (claude-user → dsh-user → project → local cascade) ∩ the merged `installed_plugins.json` of both homes (exact `name@marketplace` keys, `installPath` as the plugin root). The **write root is the dsh home** (`$DSH_HOME` / `~/.dsh`); the Claude home (`$CLAUDE_CONFIG_DIR` / `~/.claude`) stays read-visible for compatibility, with dsh entries winning per key. Explicit `pluginDirs` still flattens those dirs; `[]`/`null` disables. Discovery is best-effort — missing paths and unreadable JSON mount nothing. Two MCP keys sit alongside `pluginDirs`: `mcpConfigFiles` lists the `.mcp.json` documents whose accepted servers become mcp-client instances (`[]`/`null` disables), and `mcpLoadClaudeFiles: true` restores the old all-merge MCP discovery. Default MCP discovery is gated by source: when a dsh-native file (`<cwd>/.mcp.json` or `$DSH_HOME/.mcp.json`) declares at least one server, the Claude Code files (`$CLAUDE_CONFIG_DIR/.mcp.json`, `~/.claude/.mcp.json`, `~/.claude.json`) are skipped and a notice points at `/mcp migrate` 〔src:ws:docs/plans/2026-09-05-mcp-config-source-separation.md#L68-L90〕. An explicit `mcpConfigFiles` list is honored verbatim, with no gating and no notice. It also exposes the `ccPlugins` service for live enumeration/rescan of mounted plugins (`/reload-plugins` re-reads the cascade) and the `ccPluginManager` service bound to both homes (so `/plugin` mutations land in `~/.dsh`). The glue threads the spawn-time `resolveModel` into `AgentProvider` as a
  **lazy trampoline** over the `ccModelRoutes` service:
  `(model) => ctx.get('ccModelRoutes')?.resolve(model)` — queried on every spawn, degrading to
  inherit the parent route when the service is unmounted.

- **Runtime-wide MCP singletons.** When several agent presets are standing-mounted in one runtime (the `tui` profile mounts `cc` and `vwa`), the shared `cc-services` body and its glue row are composed once per preset tree, but all trees share one root. The glue therefore publishes ONE `mcpConnections` registry from the root fiber (`ensureMcpConnections`, `src/mcpSingleton.ts:36`) and mounts each MCP server once per `serverName` under the root (`mountMcpServerOnce`, `src/mcpSingleton.ts:88`), so `/mcp` and `mcp__*` tools work in every preset's sessions. `mcpConnections` and `toolSearch` are deliberately not in the `cc-services` isolate map.

### What moved out of the glue

Two pieces that used to live in `cc-shell-glue` moved to their owning packages:

- **`model-aliases` settings-namespace registration** → the `@dsh-cc/model-aliases`
  `ccModelRoutes` service (`packages/compat/cc-model-aliases`). The glue no longer registers
  the namespace (a duplicate registration would throw); it only consumes the service lazily.
  `Config.modelAliases` was removed from the glue config.
- **Base CC-agent discovery** (`~/.claude/agents` + `<cwd>/.claude/agents` → subagent
  providers) → the `@dsh-cc/subagent-task` Task tool, which discovers per the **session**
  cwd (not the host process cwd). `Config.registerBaseAgents` was removed.

## Known limits / notes

- This bundle no longer globally mounts any agent-facing surface. Its `cordis.patch.yml` carries host-plane rows only: the tools registry swap (the `tools` disable, the `tool-executor-native` vacate, and the root-scoped `tool-executor-cc` insert), a top-level `system-prompt` restatement that pins a 39-entry `toolOrder` prefix terminated by `<unlisted-tools>`, the `web-fetch-http` egress caps (`timeoutMs: 20000`, `maxResponseBytes: 2000000`, `maxRedirects: 3`, the dsh-cc user agent), `subagent.maxActiveSubagents: 25`, the stock `session-title-llm` disable with the CC `session-title-llm-cc` remount, and the host-plane `schedule` mount 〔src:ws:docs/plans/2026-11-07-harness-0.2.2-rc.1-migration.md#L109-L113;ws:docs/plans/2026-09-30-subagent-release-valve.md#L13-L20;ws:packages/preset/cc/README.md#L10-L10〕. The glue plugin and all agent surfaces are mounted by `@dsh-cc/preset-cc` so they stay scoped to that preset.
- The tool-web executor row ships at the peer baseline (`>=0.2.2-rc.1`), so fetch-based web tooling is composed by the preset (stock `tool-web` with `fetch: false` plus the `tool-web-fetch` row), not here; see the preset's "Known limits" for the current fetch status 〔src:ws:packages/preset/cc/README.md#L10-L10〕.
- Project/local `enabledPlugins` are boot-cwd-biased (the glue is a host-plane singleton, same as `.mcp.json`). `/reload-plugins` is the live escape hatch. Plugin state is dual-home: `$CLAUDE_CONFIG_DIR` stays read-visible for discovery, while plugin-management writes go to `$DSH_HOME` (`~/.dsh`) — setting `CLAUDE_CONFIG_DIR` no longer relocates plugin writes; `.mcp.json` still hardcodes `~/.claude`.
