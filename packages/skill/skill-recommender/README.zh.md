# @dsh-cc/skill-recommender

[English](README.md) | 中文

一个只读、仅作建议的 `recommend_skill` 工具：给定任务描述，返回少量当前可见的技能名，并附相关度与前置条件证据。它是 `ctx.skills` 目录的**消费者**——绝不加载正文、执行技能、调用技能、修改调用策略或隐藏技能。**默认关闭**（`cc-skill-recommendation.mode: off`），由 `cc` 与 `vwa` preset 以暗装行的形式挂载：工具存在，`off` 时只返回关闭结果、`mode` 设置之前不跑任何 runner。

## 它做什么

- 注册一个工具 `recommend_skill`，唯一参数是 `task`（必填、非空）。调用方不能传入候选目录、路径激活结果、调用权限或计量作用域。
- 读取调用代理本已可见的目录（`ctx.skills.list({ cwd, scope })`），把每条映射为描述符：名称、描述、使用时机、来源，以及目录给出的"可被模型调用"标志。绝不调用 `ctx.skills.get()`，因此从不读取正文。
- 构建合格池：仅用户可调用（user-invocable-only）技能、禁止模型调用（model-invocation-forbidden）技能，以及同名出现多次的整组名称都会被剔除（消费者不重新实现来源优先级）；其余技能全部保留，包括与任务没有任何字面重合的技能。
- 通过可选的决策运行时对每个技能问两个问题——五档相关度评分（0..4，取期望值）与前置条件判断（0..1）。批按有效 token 预算逐项装填（设置上限与路由真实窗口取小，使用 runner 自己的估费器），共享同一截止时间。截止时间耗尽且已答前缀覆盖池的比例不低于 `min-coverage` 时，发布带 `judged`/`eligible` 计数的部分结果；低于下限——或任何 lane 错误、答案非法、身份变化——仍整批丢弃。
- 保留**同时**达到两个阈值的技能，按相关度降序、前置条件满足度降序、名称升序排序，并截断到 `max-recommendations`。
- 返回 `status`、被选中技能及其两个数值、运行时给出的 `decisionId` 以及 `advisory: true`。不生成任何理由文本：展示文案来自固定模板，并声明既有明确指令仍然生效。

它不会让原本不可调用的技能变得可调用：常规 skill 工具仍是唯一的执行入口，仍会重新解析名称并应用原有调用规则。空推荐不能覆盖强制规则；用户或更高层指令明确点名的技能按原有流程执行，无需先取得评分。

## 模式

| `mode` | 行为 |
| --- | --- |
| `off` | 默认。零 runner 调用：工具返回 off 结果，不触碰任何其他东西。 |
| `shadow` | 运行完整判断并仅为审计记录；不向模型返回名称，目录保持不变。 |
| `active` | 返回被选中的名称及其相关度、前置条件数值，以及合格池中被判断的数量。仅为建议——加载仍走常规 skill 工具。 |

`shadow` 用于在启用 `active` 之前评估部署效果；本包自身不会把任何模式升级为别的模式。

## 配置

命名空间 `cc-skill-recommendation`；原始键为 kebab-case。所有阈值都是实验性配置，而非已测量的质量保证。

| 键 | 类型、范围 | 默认值 |
| --- | --- | --- |
| `mode` | `off \| shadow \| active` | `off` |
| `timeout-ms` | 整数，100–10000；所有批次共享 | `5000` |
| `max-input-tokens` | 整数，512–16384；每批，含状态与全部问题 | `8192` |
| `max-candidates` | 整数，1–256；完整合格池上限 | `128` |
| `batch-size` | 整数，1–32；每批技能数上限（批按 token 预算装填，实际取本上限与 token 预算的较小者）| `16` |
| `max-task-chars` | 整数，64–8192 | `2048` |
| `max-metadata-chars` | 整数，128–8192；逐项，描述与使用时机合计 | `2048` |
| `min-relevance-index` | 有限数，0–4 | `3` |
| `min-prerequisites-met` | 有限数，0–1 | `0.8` |
| `max-recommendations` | 整数，1–10 | `3` |
| `cache-entries` | 整数，0–1024；0 表示禁用缓存 | `128` |
| `cache-ttl-ms` | 整数，0–300000 | `60000` |
| `min-coverage` | 有限数，0–1；截止时间部分结果要求已答前缀覆盖合格池的最小比例 | `1` |

每次调用都实时读取，因此会话中途的改动对下一次判断立即生效。缺少该配置节即采用默认值。任一非法值会彻底禁用判断：不调用 runner、结果为 `unavailable`，且问题只经日志报告一次，而不是每次调用都报。

## 安装

包名为 `@dsh-cc/skill-recommender`，由 `cc` 与 `vwa` preset 挂载（`packages/preset/cc/agent.shared.cordis.yml`），其中 `mode` 在你设置之前保持 `off`。其他 profile 或 agent 组合请显式挂载：

```yml
- id: skill-recommender
  name: '@dsh-cc/skill-recommender'
```

插件注入 `tools` 与 `skills`，两者都存在前保持 pending。它还需要可选的决策运行时（`ctx.systemoneDecisions`，并以 S1-02 的 `decision-usage` 插件发布的根 realm 桥 `ccSystemoneDecisions` 作为后备）。缺少该服务、绑定的 actor、可解析的路由或会话水位时，每次调用都是 `unavailable` 且不发生模型调用——目录完全可用。挂载本身不启用任何行为：`mode` 默认 `off`，启用某个模式是另一次配置变更。

## 缓存与请求合并

- 每个插件 fiber 一个进程内缓存：有界 LRU（`cache-entries`）加惰性 TTL 过期（`cache-ttl-ms`）。没有后台清扫、没有定时器、没有持久化——过期条目在读取时视为不存在。
- 键固定了项目、会话、代理、会话水位、任务哈希、完整作用域目录哈希、完整路由身份与 revision、问题与策略版本，以及所有影响判断的阈值。因此改动任一配置值或目录都会产生新键，而不会命中陈旧结果。
- 只缓存完整、已校验的判断；失败批次、超时或被放弃的运行不写入任何内容。
- 同键请求合并：一次 runner 调用服务全部等待者；每个调用方独立取消，自身取消时不发布任何内容；仅当最后一个等待者离开时才中止共享请求。
- 发布前会重读目录哈希、模式与调用方作用域；任一变化即把整个推荐丢弃为 `unavailable`，且该请求内不再发起模型调用。

## 隐私

请求只携带模型提供的任务与可见元数据（名称、描述、使用时机、来源）。技能正文、技能文件、配置文件、对话历史、路径激活结果以及其他作用域的技能都绝不发送。返回值只包含状态、安全名称、每项两个数值、judged/eligible 计数与运行时的 decision id。

不做任何持久化：不存任务、不存候选元数据、不新增账本文件，也不改变既有 skill-usage 遥测——推荐不是一次技能加载，绝不计为加载。聚合评估在离线的、明确脱敏的语料上进行（见下）。

## 失败行为

| 条件 | 结果 |
| --- | --- |
| `off` | `off`，零 runner 调用 |
| 合格池为空 | `recommended` 且列表为空（`judged 0 of 0`），零 runner 调用 |
| 缺少服务/actor/水位/路由；目录超界；任务或元数据超界；路由装不下两个问题（`route-cap`）| `unavailable`（带机器可读 `reason`），推荐为空 |
| lane 错误、答案非法、批次不完整；截止时间耗尽但覆盖低于 `min-coverage` 或零批已答 | `unavailable`（带机器可读 `reason`），推荐为空 |
| 截止时间耗尽且覆盖不低于 `min-coverage` | 由已答前缀得出 `recommended`，带 `judged`/`eligible` 计数（绝不入缓存）|
| 判断有效但低于阈值 | `recommended` 且列表为空 |
| 判断期间目录、作用域、模式或路由变化 | `unavailable`，旧结果被丢弃 |
| 调用方取消、插件卸载 | `cancelled`，不发布任何内容 |

以上任一种情况都不影响原始目录与常规 skill 工具。

## 回滚

- 设为 `mode: off`：工具仍存在，但返回 off 结果且零 runner 调用。
- 移除该插件行：工具被注销，进行中的判断被中止，缓存被清空。
- 无需回迁任何数据：不创建也不改写任何正文、技能文件或持久状态。

## 离线评估

语料在不调用模型、不访问网络的前提下重放纯策略层——由每个用例的预期推导出的确定性假评分器，真实驱动本包的建池、问题、分批、阈值与排序代码：

```bash
node packages/skill/skill-recommender/scripts/eval-recommendation.mjs \
  --corpus packages/skill/skill-recommender/tests/fixtures/recommendation-corpus.json \
  --mode replay
```

覆盖：互补的多技能任务、中文任务描述对英文描述（零字面重合）、缺失前置条件、显式指定技能、强制技能、路径未触发的技能（目录中不存在）、仅用户可调用技能，以及禁止模型调用的技能。脚本逐用例输出一行并给出通过率，失败时以非零状态退出；只打印用例 id 与计数，绝不打印任务文本。生产验收数字（Precision@3、缺失前置条件占比、shadow 延迟与成本）需要真实部署与人工标注语料，属于发布门禁——离线 fixture 验证的是流水线，而不是这些指标。

## 已知限制

- **仅为建议。** 结果不能扩大调用资格、不能替代强制规则，也不能等同于一次技能加载。
- **依赖元数据。** 描述单薄、没有使用时机的技能仍会被判断，但判断依据更少；绝不假设任何未声明的能力。
- **可选依赖。** 缺少决策运行时时工具是惰性的（`unavailable`），本包自身绝不降级目录路径。
- **不在默认 preset 中。** 没有任何东西会隐式启用该工具或非 off 模式；两者都是运维的显式操作。
