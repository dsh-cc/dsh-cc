## Requirements and properties

REQ-1. Protected classes (governance/task/passthrough) are never charged
against a trimmable budget.
  - Violation: a behavioral constraint or real user input becomes a trim
    candidate, i.e. it can silently disappear from the step's input.
  - Property `protected-never-charged`: `budgeted cls = false →
    charged cls bytes = 0`.

REQ-2. Admission respects the class budget.
  - Violation: the class budget stops bounding the prompt size.
  - Property `admission-preserves-bound`: `used ≤ budget ∧ fits budget used
    bytes → used + bytes ≤ budget`.

REQ-3. An oversize message is dropped at trim time, never enqueued
(`drop-oversize`).
  - Violation: a message that can never fit occupies the defer backlog
    forever, and the ledger reports a deferral that could never succeed.
  - Property `oversize-never-fits`: `oversize budget bytes → ¬ fits budget
    used bytes` (for any `used`).

REQ-4. The dedupe window is the strict comparison `delta < window`.
  - Violation: an off-by-one either suppresses a legitimately re-asserted
    notice or re-admits a duplicate one step early.
  - Properties `window-boundary-admits` (`delta = window` admits) and
    `window-below-suppresses` (`delta < window` suppresses).

## Corpus

**Authoring step (explicit, committed):** `conformance/cases.jsonl`, 55 rows,
generated by a deterministic enumeration script (no randomness, no seed) over
these bounds, then committed verbatim:

- protected classes: `governance`, `task`, `passthrough` x byte counts
  {0, 1, 7, 4096};
- charged classes (`memory`, `advisory`) x byte counts {0, 1, 7} — the negative
  control for REQ-1 (a class that *is* charged);
- admission boundary per budgeted class: `bytes = room`, `bytes = room + 1` for
  `used` in {0, 1, budget-1}, plus one zero-byte case;
- oversize: `bytes = budget` and `bytes = budget + 1` for budgets {1, 3, 4, 16};
- window: `delta` in {0, window-1, window, window+1} for windows {1, 2, 3, 8},
  with `lastAdmitted = 10`.

Every declared property has at least one covering case (REQ-4's three lemmas map
to `window-below-suppresses`, `window-boundary-admits`, `window-above-admits`
respectively). Numeric fields are canonical decimal strings; the reviewed codec
treats a missing or non-canonical field as an error, never as null.

**Implementation binding:** `conformance/adapter.mjs` imports
`packages/plugin/dsh-cc-agents/tests/fixtures/formal-design-lean/input-governance/admission-arithmetic.ts`
— a **model-local fixture, not production code** (the `@dsh-cc/input-budget`
package does not exist yet; this mirrors the `decision-quota-accounting`
precedent). When the feature lands the adapter must be re-pointed at the real
trim/dedupe projections and the fixture removed. The fixture mirrors
`Model.lean`; it is not an independent oracle, so this conformance result pins
the semantics the future implementation must match — it does not validate that
implementation.

**Known-bad mutant (declared, to be added with the real implementation):** four,
one per property family — a `charged` returning `bytes` for protected classes; a
`fits` using `<` instead of `<=`; an `oversize` that reports `false`; a
`withinWindow` using `<=`. None is wired into the committed corpus yet, because a
mutant requires a second adapter path that would double the runner's contract;
recorded here so the gap is explicit rather than implied by the case count.

## Bounds and assumptions

- A1: classes are a closed five-element set; future classes must be assigned
  a budgeted/unbudgeted status explicitly (a change here requires re-proof).
- A2: byte counts are `Nat`; saturation of `Nat` subtraction is handled by
  the `used ≤ budget` preconditions, which the caller must guarantee.
- A3: the model covers per-message arithmetic, not accumulation across a
  batch — accumulation and the backlog walk are the TLA model's property.
- A4: `charged` returns 0 for protected classes; the real implementation must
  express the same thing (skip, not charge-and-ignore) — a test must pin it.
