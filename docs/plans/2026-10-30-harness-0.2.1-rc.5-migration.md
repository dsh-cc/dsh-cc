## 3. Breaking-change inventory

**B1 Runtime invariants removed** (`f028f25667`): package deleted, `ctx.invariants` service gone, `<pkg>/invariant` subpaths gone. dsh-cc: 47 `src/invariant.ts`, 49 package.json links, 53 imports, 6 specs; 43 companions are no-op reservations, 4 install real checks (`core/tools`, `core/tool-workflow`, `hooks/hook-protocol`, `interaction/permission-rules`). Nothing mounts them at runtime — tests only.

**B2 Subagent runtime redesign**: `startActivation` (adds required `delivery`, returns `{childId, messageId?, result, dispose}`); `SubagentRun` loses `localAgent` (locality = `local` on lifecycle payloads); provider `start` becomes optional; capacity pool (`maxActiveSubagents`, default 8) reserves a slot at materialization and releases at disposal — **it counts residency, per root-parent tree, shared with managed descendants, and throws `ACTIVATION_LIMIT_REACHED` with no queue** (`manager.ts:743-748`, `:841-848`, `:1154-1180`; `activation.ts:14-36`); archive admission installed by the runtime; `drainContinuable*` → `drainChildren`/`drainDescendants`; per-spawn `toolFilter`/`persona` removed from the start request and capabilities ("the selected preset owns persona and tool composition"); `agentPreset` start field added (spawn only; fork provider declares `agentPreset: false`).

**B3 Silent break class (no tsc error)**: dsh-cc declares local looser interfaces (`packages/subagent/task/src/background-start.ts:52-74,114-116`) and spreads `toolFilter`/`persona`; `startContinuable?` is duck-typed (`:195-200`). Additional callers that bypass background-start: `packages/memory/memory/src/recall.ts:132`, `packages/memory/memory-consolidation/src/memory-job.ts:122` and the shared helper `packages/memory/memory/src/restrict-resilience.ts:76-100` pass `toolFilter` through the removed `subagents.start`; `packages/compat/cc-plugin-loader/src/agents.ts:134,243` calls `backend.start(...)` on the raw fork provider, which no longer has `start` at the new pin.

**B4 Session title split**: shared config keeps only `maxInputBytes`/`maxOutputTokens`/`timeoutMs`; `targetWords`/`targetCjkCharacters` moved into providers; unknown keys **throw**; `generateSessionTitleWithLlm` → `executeSessionTitleLlm(ctx, config, request, titleProvider, prepared)`; prompt/parse fold (~55 lines) moved into providers.

**B5 `session-persistence-jsonl` default export removed**: named `apply`/`name`/`Config` only; 27 spec files mount the now-`undefined` default.

**B6 Reminder tools moved** to preset-scoped `@deepseek-ai/dsh-tool-schedule` (three-layer delegation deny); `dsh-schedule` registers no tools. dsh-cc mounts only the service ⇒ the CC preset silently loses `schedule_create|list|update|delete`.

**B7 Working directory centralized**: `@deepseek-ai/dsh-working-directory` + `dsh-tool-working-directory` are mounted in the base bundle (inherited by every CC profile); the subagent manager **requires** the service for local children (`manager.ts:892-894`); `tool-skill` requires it; upstream `tools/run_code` requires it for agent-owned execs.

**B8 pi-ai 0.87.1 → 1.1.0** + Azure provider rename. dsh-cc's only direct dependency is `packages/test-support/cache-trajectory` (`^0.87.1`); `normalizeContext`/`TranscriptContext`/`streamSimple`/`onPayload` signature-stable; `cache_control` placement unchanged.

**B9 New required session events**: `job/registered`, `job/settled`, `working-directory/change` are appended non-ignorable ⇒ sessions written after this migration are **refused by pre-0.2.1 readers** (rollback trap). Because the base bundle mounts the service and the children manager requires it, these writes start **in this PR**.

**B10 Link-target churn**: 78 `link:` targets, exactly one broken (`runtime-diagnostics/invariants`); moves: `hooks/{hook-protocol,hooks-claude-code,hooks-codex}` → `packages/experimental/*`, `webhook/*` → experimental, plus `skill-badge`, `session-title-all-prompts-llm`, `tool-session-query`, `tool-terminal`, `tool-ralph`; `subagent-in-process-driver` deleted; `session-query/session-query` did **not** move. **Correction**: dsh-cc mounts `@dsh-cc/hooks-claude-code` — a vendored copy, not a link — so the hook surface needs a content diff against upstream `packages/experimental/hooks-claude-code` at the pin (S7), not just link repairs.

**B10b Known-event-set mutation (pre-existing)**: dsh-cc registers its own session event names into the live `KNOWN_SESSION_EVENT_TYPES` set (`worktree/entered` at `session-cwd/src/events.ts:24`, `permission/mode`, completion-gate, progress-rebuild). Upstream deliberately excludes downstream names and rejected name registration (`core/session/src/known-event-types.ts:15-20`); a reader that has not loaded those modules — including a stock `dsh` binary — refuses such sessions. This PR's B9 events are not the only cross-version trap; S7 adds the resume tests and records the `ignorable` decision.

**B11 Tools fork deltas**: `PreToolDecision`/`PostToolDecision` unions live in `packages/core/tools/src/index.ts` (`:607`, `:617`) and the file did change in-range (54 lines) with **no union/kind change** — the "byte-identical" phrasing of v1 overstates it; re-derive at S5 against the actual type site. Real deltas: fork `invariant.ts`; `'both'` mode removed upstream (fork keeps it); `presentationMeta` projected for nested calls (fork guards `exec.parent === undefined` at `runtime-results.ts:113`); `PtcDispatchEventData.meta`; **the fork's `tool/code-dispatch` writer discards `result.meta`** (`code-mode.ts:310`), so typing alone does not fix persisted metadata; `run_code` now resolves a working directory upstream (`index.ts:949-970`) while the fork passes none and documents "The working directory is the Session's current directory" (`code-mode.ts:473`); persistent PTC.

**B12 Composition/drift fixtures**: `preset/cc/tests/composition.spec.ts` curated baseline vs upstream `standard` preset (4 unlisted divergences after upstream additions); `cc-acp/tests/upstream-drift.spec.ts` unlisted lines.

## 8. Design questions and risks

**DQ1 — child composition**: decided (C5/S3) as **listener-primary with a durable plan** — no preset synthesis (the descriptor cannot carry a preset id, an explicit preset would have to duplicate the CC composition, and a shared preset cannot preserve the ephemeral post-sanitize strip). Residual risks: the listener must return `undefined` and use `agent.ctx`; the plan must be re-applied on `source:'resume'` for fork/one-shot children; pre-migration children are skipped by the formation marker so upstream's legacy descriptor restore is not duplicated.

**DQ2 — capacity**: answered from source — one pool per root activation tree (root holds no slot), local and external descendants share it, residency not `running`, slot reserved before `agents.create` yields and released after disposal, follow-ups to a resident take no new slot while cold resume does, no queue, throws at `maxActiveSubagents`. Host row set to 25, dsh-cc's running-count refusal deleted or delegated, copy rewritten. Users can still override via settings.

**DQ3 — rollback trap (B9)**: live in this PR; README note is release-blocking; no in-repo mitigation.

**DQ4 — silent breaks**: tsc cannot see B3; the §6 behaviour gates are the net; fakes that implement the obsolete capabilities must be fixed to the real shape or deleted.

**DQ5 — unknown cluster**: bisect rule in S7; quarantine with evidence, never silently absorb.

**DQ6 — `formal-design-*` 120 s driver timeouts**: isolated re-run decides; record evidence either way.

**DQ7 — two cwd owners during the PR-B window**: S10's mirror + spec makes them agree; PR-B removes the mirror. Any cwd-touching feature landing before PR-B must re-run the S10 spec.
