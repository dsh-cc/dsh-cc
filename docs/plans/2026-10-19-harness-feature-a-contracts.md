# Feature A: experiment contracts, snapshots, and persistence

- Status: proposed.
- Parent: [Harness experiments](2026-10-19-harness-experiments.md).
- Package: `packages/evaluation/harness-contracts` (`@dsh-cc/harness-contracts`, private).
- Dependencies: none of the other proposed features.

## 1. Problem and solution

Session configuration attribution does not capture every input that changes agent behavior. A resumable workflow does not prove that its files, tools, model route, or memory are unchanged. Without a frozen identity, an experiment can compare different environments or reuse stale results.

Create a content-addressed snapshot of the effective harness and task inputs. Persist every experiment, execution attempt, and decision under a dedicated store. Require exact identity checks before resume or reuse. This package owns schemas, hashing, and storage; it never starts an agent or makes a quality judgment.

## 2. Serialization and identifiers

All persisted JSON uses schema version `1`, JSON Schema Draft 2020-12, and `additionalProperties: false` recursively except declared arbitrary JSON maps. Use Ajv 8 strict mode. Every API accepts `unknown`, validates it, and only then exposes typed data. Generate TypeScript types from the schemas during development and check the generated output in CI. Changing any field semantics requires a new schema version, not a silent reinterpretation.

Canonical JSON recursively sorts object keys by JavaScript UTF-16 code-unit order, preserves array order, uses JSON number spelling, and emits no whitespace. Reject undefined, nonfinite numbers, unpaired surrogates, duplicate JSON object keys, and integers outside the safe range. Read raw JSON with a duplicate-key-rejecting parser before Ajv validation. Hash raw file bytes without newline or Unicode normalization. A `Digest` is `sha256:` followed by 64 lowercase hexadecimal characters. A blob's address is its raw-byte digest. Object digests are SHA-256 of canonical JSON UTF-8 bytes. Never include an object's own digest field in its preimage.

Identifiers are generated by the host: `exp_`, `run_`, `att_`, `cand_`, `dec_`, or `les_` followed by a lowercase UUID v4. User input cannot supply a new identifier. Timestamps are RFC3339 UTC with milliseconds and are descriptive; ordering uses sequence numbers, not clock time. All lists that represent sets are sorted and duplicate-free. Other arrays retain their semantic order.

Paths in manifests are relative POSIX paths. Reject absolute paths, empty segments, `.`, `..`, backslashes, NUL, and any segment beginning with a drive prefix. Reject symlinks, sockets, devices, and hard-linked input files (`nlink > 1`) rather than dereferencing them. File modes are `0644` or `0755`; modes participate in the file manifest digest. Directories are implicit. Apply a 10 MiB per text file, 100 MiB total input, and 10,000-file limit. Exceeding a limit returns `LIMIT_EXCEEDED`; never truncate identity-bearing content.

## 3. Normative records

The following is the required logical shape. `JsonObject` means a JSON object using the serialization rules above. Optional properties are omitted, never null, unless explicitly nullable.

```ts
type FileRef = { path: string; blob: Digest; bytes: number; mode: 420 | 493 };
type Route = {
  alias: string; providerId: string; modelId: string;
  revision: string | null; adapterDigest: Digest;
  effectiveOptions: JsonObject;
};
type Snapshot = {
  schemaVersion: 1;
  repositoryCommit: string; dshCcVersion: string; harnessVersion: string;
  runtimeImageDigest: string; launcherDigest: Digest;
  routes: { solver: Route; proposer: Route | null; selector: Route | null; reviewer: Route | null };
  files: FileRef[];
  tools: { name: string; schemaDigest: Digest; descriptionDigest: Digest; implementationDigest: Digest }[];
  plugins: { id: string; version: string; sourceDigest: Digest; config: JsonObject }[];
  environment: { name: string; value: string }[];
  policyDigest: Digest; validatorDigest: Digest;
  networkPolicyDigest: Digest; seedPolicyDigest: Digest;
};
type Task = {
  schemaVersion: 1; taskId: string; familyId: string; domain: string;
  partition: 'development' | 'holdout'; prompt: Digest;
  inputs: FileRef[]; outputPaths: string[];
  adapterId: string; adapterDigest: Digest; validatorDigest: Digest;
};
type Experiment = {
  schemaVersion: 1; experimentId: string; createdAt: string;
  baselineSnapshot: Digest; taskManifest: Digest; scoringManifest: Digest;
  policy: Digest; budget: Digest; plan: Digest;
};
type Run = {
  schemaVersion: 1; runId: string; experimentId: string;
  taskDigest: Digest; snapshotDigest: Digest;
  variantId: 'baseline' | string; repetition: number; seed: number | null;
  executionKey: Digest;
};
```

`files` contains the effective system prompt, resolved instructions, selected skills and their helpers, agent definitions, selected memory, tool guidance, hook definitions, configuration templates, and dependency lockfiles as staged, rather than just their source filenames. Secret-bearing files are forbidden. Store the resolved route from the same prepared host handle that dispatches the call; resolving an alias again after hashing is forbidden. Freeze streaming and reasoning options, output limits, tool definitions, and adapter code identity. `revision: null` explicitly means the provider does not expose a pinned revision; do not use reasoning effort as a model version. Such snapshots support reproducibility of configuration, not deterministic provider behavior.

`environment` permits only `LANG`, `LC_ALL`, and `TZ`; defaults are `C.UTF-8`, `C.UTF-8`, and `UTC`. B constructs all other runtime values. Credentials, tokens, endpoints with credentials, and arbitrary process environment values MUST NOT enter snapshots. Routes identify a logical provider, not a credential. Provider endpoint mapping is included in the trusted launcher digest without secret bytes.

`scoringManifest` is a digest of the complete trusted evaluator configuration including sealed annotation digests. Its bytes are stored in a separate controller-only store. Neither that object nor sealed labels is present in the executor blob mount. A stores references but does not materialize them for B.

## 4. Hash scopes

- `snapshotDigest = hash(Snapshot)`; this captures effective harness behavior and execution environment, not quality labels.
- `taskDigest = hash(Task)`; the prompt and input file bytes participate through their blob references.
- `executionKey = hash({snapshotDigest, taskDigest, repetition, seed, runnerProtocol: 1})`.
- `experimentDigest = hash(Experiment)`; identity includes policy, budget, and scoring manifests.
- A result identity additionally includes output and trajectory manifest digests. Evaluation identity includes result identity, scoring manifest, evaluator code digest, and evaluator route.

A changed task, helper mode, prompt, model option, memory file, tool schema, network policy, image, or adapter invalidates execution reuse. A changed scorer invalidates evaluation reuse but need not invalidate a clean frozen execution. A changed budget starts a new experiment; continuation cannot quietly raise a cap. Repetition is part of the key so independent samples never collapse into one cached result.

## 5. Store and write protocol

The CLI accepts `--store <absolute-path>`; default is `<dshHome>/harness-experiments`. Canonicalize the store root and require that it is outside all task, repository-output, and candidate materialization roots. Create it with mode `0700`; files use `0600`. The layout is:

```text
blobs/sha256/<hex>
experiments/<experimentId>/experiment.json
experiments/<experimentId>/events.jsonl
experiments/<experimentId>/HEAD.json
experiments/<experimentId>/runs/<runId>/attempts/<attemptId>/result.json
experiments/<experimentId>/decisions/<decisionId>.json
```

The text block is a file layout, not an executable command. Controller-only scoring blobs live in a sibling `sealed/` directory with no executor mount. Blob writes use a same-directory temporary file, fsync, rename, and directory fsync. Existing blobs are byte-verified; a mismatch is `STORE_CORRUPT`. Immutable object files use exclusive creation; identical existing bytes are idempotent, different bytes fail.

A single writer owns an experiment using an exclusive lock directory with owner PID, machine ID, and a random token. A dead PID on the same machine permits explicit `recover`; unknown remote ownership fails `STORE_LOCKED`. No timed automatic lock stealing. Every mutable command acquires this lock before inspecting HEAD.

Each event contains `{schemaVersion, seq, previousEventDigest, kind, payload, digest}`. `seq` starts at 1. `digest` covers every field except itself. Append one complete newline-terminated event and fsync before atomically updating HEAD to `{seq, digest}`. HEAD is an acceleration index, not the authority. On recovery, validate the chain and rebuild HEAD. Ignore and quarantine only an incomplete final line; a malformed complete line or a broken chain is `STORE_CORRUPT` and prevents resume. Never skip a corrupt middle event. Event payloads reference immutable records; write those records before their events.

## 6. States, API, and errors

Experiment states are `created → preflighted → running → sealed → evaluated → decided`. Any nonterminal state may become `cancelled` or `failed`. `sealed`, `evaluated`, and `decided` are checkpoints; resume continues only unfinished work and never changes completed records. A sealed experiment's executions cannot be extended; additional tasks or candidates require a new experiment. A failure records a stable code and stage. `failed`, `cancelled`, and `decided` are terminal experiment states and cannot resume; interrupted stages leave the experiment running until explicit recovery settles them. Recovery records a new event rather than deleting an earlier event. Recovering storage does not reopen a terminal experiment.

Public exports: `contracts` (schemas, generated types, canonicalJson, digests), `snapshot` (`captureSnapshot`, `diffSnapshots`, `verifySnapshot`), `store` (`createExperiment`, `openExperiment`, `appendEvent`, `recover`), and `budget` (`createLedger`, `reserve`, `markDispatched`, `settle`, `reconcile`). `captureSnapshot` receives an explicit materialized file inventory and prepared-route descriptors; it does not discover a user's home directory. `verifySnapshot` verifies every referenced nonsealed blob before execution. `appendEvent(expectedSeq, event)` rejects a stale sequence with `REVISION_CONFLICT`.

Shared error shape is `{code, stage, message, retryable, references: string[]}`. Codes are `SCHEMA_INVALID`, `LIMIT_EXCEEDED`, `IDENTITY_MISMATCH`, `STORE_CORRUPT`, `STORE_LOCKED`, `REVISION_CONFLICT`, `PREFLIGHT_FAILED`, `ISOLATION_UNAVAILABLE`, `BUDGET_EXHAUSTED`, `USAGE_UNKNOWN`, `EXECUTION_FAILED`, `OUTPUT_INVALID`, `EVALUATION_FAILED`, `DECISION_INCONCLUSIVE`, and `CANCELLED`. Later features use these codes and may add an explicitly versioned detail code. Human messages never determine control flow. Default retryable is false; B defines dispatch retry behavior.

There is no schema migration in v1. An unknown version opens read-only for raw export only, returns `SCHEMA_INVALID` for commands, and MUST NOT be cast to v1.

## 7. Shared budget seam

A owns the budget ledger implementation so B and C do not depend on D. The complete admission and settlement algorithm is specified in [D, Section 5](2026-10-19-harness-feature-d-optimization.md); implement that shared algorithm with A, before B can dispatch. D adds scheduling, not a second ledger. Budget records are immutable blobs with ledger transitions in the experiment event chain.

`reserve({callId, role, inputUpperBound, outputUpperBound, costUpperBoundMicroUsd, expectedSeq})` atomically returns a reservation ID or `BUDGET_EXHAUSTED`. `markDispatched(reservationId, brokerReceipt)` is idempotent for the same receipt. `settle(reservationId, usage, dispatchEvidence)` is idempotent for identical data and rejects conflicting data. `reconcile(reservationId, verifiedBrokerRecord)` may replace unknown accounting with measured usage through a new event; never edit the previous reservation. Fields are nonnegative safe integers. Call IDs are controller-generated UUID v4 strings. There is one ledger per experiment; all roles, execution attempts, and evaluator calls use it. Offline deterministic scoring incurs zero model usage. A confirmation experiment has its own budget and ledger.

Add tests for competing reservations at a cap, duplicate settlement, unknown dispatch, over-bound usage, restart/reconciliation, and elapsed-time accumulation. Feature A is incomplete without these tests even though it makes no actual model calls.

## 8. Acceptance and TDD sequence

Write failing tests in this order, then implement the smallest behavior that satisfies each row:

| Case | Required outcome |
| --- | --- |
| Reordered object keys; unchanged raw file bytes | Identical object digest |
| CRLF versus LF, changed mode, skill, route option, tool schema, memory, or image | Different snapshot digest |
| Unknown provider revision | Explicit null; no claim of pinned model behavior |
| Credential in a proposed snapshot or forbidden environment name | Reject before persistence |
| Symlink, hard link, traversal path, oversized input, duplicate JSON key | Reject without reading outside the input root |
| Identical immutable write repeated | No extra object or event |
| Crash after event fsync, before HEAD update | Recovery rebuilds HEAD exactly |
| Incomplete final line versus corrupt complete middle line | Quarantine tail; fail on middle corruption |
| Two writers or stale expectedSeq | One writer succeeds; other gets a stable conflict |
| Changed scorer only | Execution identity unchanged; evaluation identity changes |
| Missing blob or unsupported schema | Fail closed; no dispatch |

Run package unit tests and a local-filesystem crash-recovery integration suite. A full model call is neither necessary nor sufficient to validate A.
