## 1. Goal and non-goals

Bring dsh-cc onto harness 0.2.2-rc.5 with zero behavioral regressions on the CC-compatible surface, same discipline as the 0.2.1-rc.5 (PR #317) and 0.2.2-rc.1 (PR #344) migrations. Two behavior deltas are accepted explicitly (D5 `wait_agent` in the pinned control-tool block; upstream `send_message` targeting by name) — §8.

Non-goals: adopting the new upstream Agent Teams surface (deliberate non-adoption, parity stays `engine.agent-teams: missing`); converging the settings fork; upstream web-app-only rows; local profile pool resync (environment task, listed in §7 for the record).

### 3.3 S3 — `send_message` name targeting (R2)

`subagent/resume-pins/src/plugin.ts:307` and `src/dispatch-admission.ts:16`: read `arguments.agent` instead of `arguments.agent_id`. The gates key pins and tombstones by child id; a bare string compare against `args.agent` is insufficient when the parent named its children (the model-facing name differs from the Session id; the name IS the id only for unnamed creators — harness `subagent/src/types.ts:53-56`). Resolution: resolve the target to a child id inside the gate before pin/tombstone lookup, using the subagents service (`resolveName(sender, agent, signal)` where a sender is available; fall back to treating the raw value as an id). Keep the gate a no-op pass-through when resolution is unavailable — never block foreign children. `plugin.ts:379` reads `subagent_id` from a different (dsh-cc-owned) tool — leave untouched. Add a regression spec: a named pinned child + `send_message` with its NAME must still hit pin admission (this is the silent-pass-through regression this slice exists to fix).

## 5. Risks

- **R-name-resolution (S3)**: `resolveName` needs a sender agent and a signal; the `tools/pre-execute` gate has both (`exec.agent`, `exec.signal`). If `resolveName` throws for foreign names, catch and pass through — the gate must never block a legitimate message to a non-pinned child.
- **R-capacity (S4.3)**: the standalone `listChildren(ctx, id, signal)` signature differs from the old service method; if adoption turns out to need a bigger refactor of `live-capacity`, fall back to keeping the optional seam with an explicit degrade comment — but then add a tripwire spec that the degrade is visible.
- **R-drift-allowance creep (S5/S6/S7)**: every allowance entry needs a one-line justification in the PR body; a fold is preferred over an allowance wherever the upstream change is semantically neutral to the cc factorization.
- **R-rest-bucket (S8.4)**: pinning `wait_agent` must keep `tool-order-catalog.spec.ts`'s rest-bucket assertion coherent (one rest marker, no duplicates, registered-only names).

## 6. Review protocol

Three-seat blind review (critic + grok lane + codex lane) on this document, per the standing design-work gating order: probes already ran (baseline + deterministic repros above); the review evaluates this design; all findings adjudicated (fold with code-level re-verification or reject with evidence) before implementation; delta re-review on the same revision for any seat that returns NO-GO/GWC findings. Review ledger (per-round verdicts + dispositions) lands in `.scratch/migration-rc5/` and the PR body carries the summary.
