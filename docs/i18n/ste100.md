# English README writing rules

Use [ASD-STE100 Issue 9](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf) for English README prose.
Keep the Chinese text consistent with the English text. The two languages have equal authority.

## Sentence and paragraph checks

- Use a maximum of 20 words in each instruction sentence.
- Use a maximum of 25 words in each description sentence.
- Use a maximum of six sentences in each paragraph.
- Give one topic in each paragraph.
- Use the active voice. Give instructions with command verbs.
- Put conditions before instructions.
- Use the same name for the same item.
- Use American spelling.

Use the dictionary's approved meaning and part of speech. Short sentences alone do not make a text STE.
For example, use “usually” for “normally” and “necessary” for the verb “need”.
Use “in” for the preposition “inside”. Use “approved” for “authorized”.

## Technical vocabulary

Rules 1.5 through 1.13 permit technical nouns and technical verbs.
Use the software meanings below. Do not classify an unrelated general word as a technical term.

| Area | Technical nouns and their meanings |
| --- | --- |
| Product names | dsh-cc, DeepSeek Harness, Claude Code, Serena, Codex, Grok, Moonshot, Z.AI, and model names |
| Software units | plugin, bundle, package, launcher, profile, preset, runtime, host, client, server, binary, and repository |
| Agent operation | agent, subagent, skill, persona, workflow, tool, hook, prompt, session, task, background job, and foreground |
| Model configuration | model, provider, alias, route, parent route, default model, inheritance, token, and model call |
| Data and files | file, directory, path, workspace, worktree, checkout, cache, index, metadata, payload, schema, and lockfile |
| VWA author data | article body, source evidence, excerpt, claim, argument, premise, warrant, research contract, and argument graph |
| VWA review data | finding, assessment, evidence grade, review budget, frozen limit, artifact binding, report, receipt, and delivery status |
| VWA status labels | pending job, incomplete job, reviewed candidate, unverified draft, and confirmed delivery |
| Software interfaces | CLI, TUI, UI, MCP, OAuth, HTTP, JSON, YAML, PATH, stdin, stdout, ANSI, IDE, API, and CI |
| Software processes | configuration, installation, discovery, authentication, compaction, consolidation, compression, indexing, debugging, and initialization |

Technical verbs for computer processes include these words:

- Install, uninstall, update, upgrade, load, mount, and boot software.
- Configure a model route or enable a tool.
- Register evidence, bind an artifact, review an argument, and render a report.
- Export a transcript, refresh a panel, sanitize a tool list, and resolve a path.
- Sync a profile, inherit a route, and dispatch a task.

Keep literal tool names, paths, settings, status labels, code, and user-interface text unchanged.
They must continue to agree with the runtime.
A generated compatibility table must agree with the capability manifest.

## Bilingual review

Compare the English and Chinese instructions in order. Check these items in each pair:

1. Product scope and optional features.
2. Commands, configuration keys, defaults, and restart conditions.
3. Model routes, fallback behavior, and review limits.
4. User permissions, result states, and unresolved limitations.
5. Links, code samples, version tables, and component counts.

After the review, update the package pairing record with `node scripts/check-readme.mjs --write`.
The pairing record detects changes. It does not prove that the translation or STE usage is correct.
